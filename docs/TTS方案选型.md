# MiniNovel TTS 方案选型与接入设计

> 版本：v0.1  
> 日期：2026-10-07  
> 状态：方案已选定，待本机样例验证  
> 前端形态：Web  
> 关联文档：[产品策划文档](产品策划文档.md)

## 1. 选型结论

MiniNovel 采用 **Qwen3-TTS + MLX-Audio** 作为 macOS 本地配音的主要方案。

前端采用 Web：浏览器负责角色音色分配、试听、批量任务提交和结果展示；运行在 Mac 上的本地 TTS 服务负责模型加载、语音生成、文件保存与格式转换。

推荐配置：

| 用途 | 模型 | 选用原因 |
| --- | --- | --- |
| 正式配音，优先验证 | `mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-8bit` | 有固定预设音色，原始 1.7B 模型支持情绪与风格指令 |
| 快速预览，可选 | `mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-8bit` | 模型更轻量，有相同系列的预设音色，适合先验证预览效率 |
| 开发阶段后备 | macOS 系统语音 | 能枚举系统音色，不需要部署额外神经网络模型 |
| 轻量替代候选 | Kokoro-82M 的 MLX 版本 | 模型小，有中文音色；需重点评估中文与短对白效果 |

第一版先实现并验证一个 Qwen3-TTS 正式配音档位，快速预览和后备引擎可以后续加入。正式配音档位在当前机器上的速度若不满足需求，再根据实测调整默认模型。

文本、图片和动态视频继续使用产品中的 Agnes 默认配置。TTS 独立选型，与 Agnes 的三模态接口解耦。

## 2. 需求与判断依据

本方案必须满足：

1. 生成音频前，为每个角色及旁白分配固定音色。
2. 用户一键提交整集或选定范围，按段落生成音频。
3. 在 macOS 本机运行，下载模型和依赖后可本地推理。
4. 每段对白或旁白输出一个独立 MP3，支持试听、重试和替换。
5. 修改某段文字只更新该段；更换角色音色只更新关联段落。
6. 以真实音频时长驱动字幕与画面时间轴。
7. 能由 Web 前端使用，不要求用户在终端逐句运行命令。

“批量生成”首先是一种产品操作：一次提交多个段落，后台排队处理。它不要求同时对所有段落进行模型推理。

## 3. 候选方案比较

| 方案 | 音色选择 | macOS 本地能力 | 情绪控制 | 主要限制 | 定位 |
| --- | --- | --- | --- | --- | --- |
| Qwen3-TTS CustomVoice + MLX-Audio | 9 个预设音色；其中 5 个中文原生音色，包含方言特色 | 支持 Apple Silicon，由 MLX 推理 | 原始 1.7B 版本支持指令控制，实际 MLX 效果需验证 | 需要下载模型，长音频占用和生成速度需本机测试 | 首选 |
| Kokoro-82M + MLX-Audio | 中文预设音色 8 个，4 女声、4 男声 | 支持 Apple Silicon | 不作为首版情绪演绎方案 | 官方提示非英语支持与短发言效果存在差异 | 轻量候选 |
| macOS 系统语音 | 可枚举已安装声音，部分声音需另行下载 | 系统原生支持 | 不作为小说情绪控制方案 | 自然度、角色表现力和声音可用性依赖系统声音 | 开发后备 |
| 云端 TTS | 由供应商提供音色目录 | 可在 Mac 上调用，但推理在云端 | 取决于供应商 | 网络、计费、数据上传和服务限制 | 后续可选适配 |

选择 Qwen3-TTS 的主要原因是固定音色适合长期绑定角色，中文能力和 1.7B 指令控制符合小说对白需求，MLX-Audio 又提供了 Apple Silicon 的运行路径。

这是一项基于文档能力的选型，尚未完成不同模型的本机音质对比。

## 4. 当前 Mac 的运行建议

本次读取到的开发机器配置：

- 芯片：Apple M1。
- 内存：16 GB。
- 系统：macOS。

初始建议使用 1.7B CustomVoice 8bit，单模型常驻，逐段排队生成。它具备在 Apple Silicon 上运行的文档依据，但当前尚未实测加载峰值、长段落内存和生成速度，不承诺实时生成。

运行环境包含：

- Python 3.10 或以上，具体版本与依赖版本在实现验证后锁定。
- MLX-Audio 及其 MLX 依赖。
- 已下载到本机的模型权重及相关资源。
- FFmpeg，用于 MP3 编码和音频检测。
- 本地项目素材目录与任务存储。

模型下载完成后，常规推理应使用本地缓存，不在每个段落开始时重复下载或加载模型。首次安装和模型下载需要网络；本地离线能力应在验收时实际断网验证。

Mac 的统一内存还要供浏览器和视频渲染使用。首版避免高并发 TTS 与视频渲染同时运行，具体调度在实测后调整。

Intel Mac 不属于本次 MLX 本地方案的支持目标；后续可通过其他引擎或云端适配支持。

## 5. 音色选择与角色绑定

### 5.1 预设音色

优先使用 CustomVoice 的预设说话人，不在首版引入声音克隆或自由音色设计。

官方列出的中文原生音色如下。角色用途仅是试听建议，不是强制映射。

| 音色 ID | 官方声音描述 | 建议试听用途 |
| --- | --- | --- |
| `Vivian` | 明亮、略带锋芒的年轻女声 | 活泼、强势或情绪鲜明的年轻角色 |
| `Serena` | 温暖、柔和的年轻女声 | 温柔角色或女旁白 |
| `Uncle_Fu` | 低沉、醇厚的成熟男声 | 成熟男性、长辈或男旁白 |
| `Dylan` | 清晰自然、带北京口音的年轻男声 | 年轻男性角色 |
| `Eric` | 活泼、略带沙哑、带四川口音的男声 | 有方言特色的角色 |

另外还有英语原生音色 `Ryan`、`Aiden`，日语原生音色 `Ono_Anna` 和韩语原生音色 `Sohee`。官方说明预设说话人可以生成支持的语言，但建议使用其原生语言以获得较好效果。中文作品默认优先展示中文原生音色。

上线时由实际加载模型的能力信息核对音色列表与 ID；不要只依赖界面中硬编码的名称。

### 5.2 角色音色页面

页面列出所有有声角色与旁白，每项包含：

- 角色名称、简单人物说明、对白段数。
- 当前引擎、模型、音色和语言。
- 固定试听样例与该角色实际台词试听。
- 角色默认演绎指令，例如“平静、语速自然”。
- 待生成、已生成、失败和过期的音频数量。

用户完成音色分配后再开始正式批量配音。允许多个角色采用同一音色，提示辨识度可能降低，但不强制阻止。

### 5.3 绑定数据

每个角色保存以下信息：

| 字段 | 用途 |
| --- | --- |
| 角色稳定 ID | 关联所有幕中的同一角色 |
| TTS 引擎 ID | 区分本地 Qwen、系统语音及未来其他供应商 |
| 模型标识与版本 | 防止模型变化后混用生成结果 |
| 音色 ID | 稳定选择预设声音 |
| 语言 | 中文作品默认明确设置中文 |
| 默认演绎指令 | 角色基本表达风格 |
| 绑定版本 | 判断相关 MP3 是否需要更新 |

旁白采用单独的说话人 ID，参与相同的绑定、生成与试听流程。

## 6. 配音控制与模型差异

### 6.1 1.7B 与 0.6B

Qwen 官方能力表列出 1.7B CustomVoice 支持指令控制；0.6B CustomVoice 未列出该能力。

因此：

- 1.7B 档位可提供演绎指令输入，MLX 后端接入和效果须实测。
- 0.6B 档位不承诺情绪指令控制，界面按能力禁用或隐藏相应控件。
- 如果未来同一项目使用不同档位，试听与正式生成使用的模型必须清楚显示。

预设音色绑定能固定声音来源，但不同段落的情绪、语调和音色一致性仍需试听确认。

### 6.2 朗读文本与控制信息分开

段落分别保存：正文文本、朗读文本、说话人、演绎指令、发音备注和段前段后停顿。

例如“愤怒地说”属于演绎指令，不拼接进正文朗读；人物动作和舞台说明也不能进入音频。

专名、多音字、数字等可在朗读文本中进行明确改写，字幕保留正文。不能把所有发音备注都假定为模型支持的音素参数，实际支持方式由适配器明确。

语速和音量控件只有在对应后端经过验证后才启用。后期增益与音频时长处理，应与模型演绎控制分别记录。

## 7. Web 前端与本地 TTS 服务

### 7.1 第一版连接方式

建议在同一台 Mac 上运行 Web 应用后端和本地 TTS 服务：

**Web 浏览器 → 应用后端 → 本地 TTS 服务 → 模型推理与音频文件。**

- 浏览器通过应用后端提交角色配置、试听和批量任务。
- 应用后端维护项目、段落、内容快照与任务状态。
- Python 本地 TTS 服务加载模型，执行语音生成和音频处理。
- 应用后端把任务进度和可播放音频地址返回浏览器。

浏览器不直接执行 Python 或加载 MLX 模型。本地 TTS 服务也不需要访问 Agnes API Key。

初版优先让应用后端统一代理 TTS 请求和音频文件，避免浏览器跨来源访问本地服务带来的连接与权限差异。

### 7.2 本地服务职责

1. 报告服务状态、当前模型和模型加载状态。
2. 提供可用音色与已验证控制能力。
3. 执行单段试听和批量配音任务。
4. 保存真实音频、音频时长、实际输入和生成版本。
5. 提供失败重试、任务取消和恢复信息。
6. 控制模型生命周期与推理并发。

服务只监听本机回环地址，接收经过应用验证的任务和受限文件目标；不默认向局域网或公网开放。

### 7.3 后续线上部署

Web 前端部署到线上后，云端后端不能直接访问用户 Mac 的本地服务。本地配音需要一个明确的本地连接机制。

推荐保留一个在 Mac 运行的轻量本地服务，由它主动连接经过用户授权的线上应用，获取配音任务并回传结果。需要云端预览或渲染时，明确传输音频；全文本地模式则由本机保存与渲染。

线上网页直接请求本机端口会涉及浏览器对本地网络访问、来源与协议的限制，不作为首版默认架构。

线上部署及本地连接器在后续技术设计中确定。本次明确的是 Web 前端与 Mac 本地推理的职责划分。

## 8. 批量生成流程

1. 用户确认所有需要配音的文字，并完成角色与旁白音色分配。
2. 应用检查本地服务和模型状态，汇总待生成段落与可复用音频。
3. 用户确认批次，保存文字、说话人、音色和演绎设置的快照。
4. 后台建立逐段任务，初版按队列顺序处理。
5. 每个任务解析角色绑定，并将朗读文本与演绎信息传给模型。
6. 合并模型为同一段落输出的内部音频片段，保存一份 WAV 母版。
7. 编码为 MP3，检查解码和时长，登记结果与版本。
8. 前端持续展示进度，用户可以试听已完成的段落。
9. 失败项保留错误原因，其他段落继续执行。
10. 全部音频确认后，以实际时长更新字幕和镜头时间轴。

模型只加载一次，避免逐段重复初始化。MLX-Audio 文档提供 Qwen 的批推理接口，后续可以验证小批量并行；实际启用前须检查内存、分段结果和控制参数兼容性。

试听属于单独任务，不替代正式批次的内容确认。相同输入的已确认音频可以复用；用户选择“重新演绎”时允许生成新候选。

## 9. 音频输出与版本管理

### 9.1 输出文件

每个有声段落交付：

- WAV 母版，用于后续视频渲染和音频处理。
- 独立 MP3，供用户试听、下载及素材导出。
- 生成清单，记录段落 ID、输入版本、模型、音色、实际采样率、时长和文件校验信息。

优先用 WAV 母版参与最终视频渲染，再编码成成片音轨，减少重复有损压缩。MP3 仍按产品要求逐段保留。

文件名使用稳定段落 ID 与素材版本，不依赖可变化的幕序号。模型若将长段落拆成多个内部片段，需要先合并再交付一个段落文件。

### 9.2 复用规则

音频是否可复用，至少依据：

- 朗读文本与发音处理。
- TTS 引擎、模型版本和音色。
- 语言、演绎指令及有效生成参数。
- 音频后处理配置。

缓存用来复用已存在且有效的文件，不承诺随机生成模型每次输出一致。

| 修改 | 更新范围 |
| --- | --- |
| 一段朗读文本、发音或演绎指令 | 该段音频及关联时间轴 |
| 一个角色的音色或默认演绎设置 | 使用相应设置的该角色段落 |
| 幕或段落顺序 | 重排时间轴，可复用段落音频 |
| 图片或动态镜头 | 更新画面，音频可继续复用 |
| 字幕字号、颜色或换行 | 更新字幕渲染，无需重新配音 |
| 模型或引擎 | 影响新批次；切换已有段落时需明确重生成范围 |

生成中的输入若已被用户修改，完成结果保存为旧版本候选，不覆盖当前段落。

## 10. 音频与字幕对齐

初版以真实音频时长定位段落级字幕，再结合标点和停顿分配长段内部字幕块。没有可靠时间标记时，内部划分属于估算，允许人工修正。

后续可评估 MLX-Audio 支持的 `Qwen3-ForcedAligner`，使用已有朗读文本和生成音频获取更细的时间标记。

对齐模型是独立环节，不属于 CustomVoice 自带能力，不能直接承诺 TTS 返回精准逐字字幕。其中文标记质量和与实际 MP3/WAV 的时间一致性需要单独验收。

配音和视频最终处理改变音频长度时，要重新计算关联时间数据。

## 11. 验证计划与通过标准

### 11.1 样例集合

先用三名角色和一名旁白制作约 20 段测试台词，覆盖：

- 正常多轮对白。
- “嗯？”“什么？”等极短发言。
- 较长旁白和明显的标点停顿。
- 专名、多音字、日期、金额与中英文混合。
- 同一音色的平静、怀疑、愤怒和悲伤演绎。
- 同一角色跨多段的声音一致性。

在相同文本上比较 1.7B 与 0.6B，再确定预览档位是否值得引入。

### 11.2 验收指标

| 验证项 | 通过要求 |
| --- | --- |
| 模型加载 | M1、16 GB 机器能成功加载并连续执行测试集，无内存导致的失败 |
| 音色选择 | 页面选择的音色与实际请求、结果记录一致 |
| 多角色批量 | 每段使用对应角色音色，没有错误映射和漏段 |
| 中文自然度 | 实际试听并记录结论，不仅检查文件生成成功 |
| 指令控制 | 1.7B 的 MLX 路径能接收指令，试听中验证可用效果 |
| MP3 输出 | 每个有声段落对应一个可解码 MP3，时长有效 |
| 时间轴 | 音频真实时长进入字幕和画面安排 |
| 局部更新 | 修改一段不重生成其他未受影响音频 |
| 失败恢复 | 刷新页面不丢任务结果；进程重启后已完成段落不重复生成 |
| 输入冲突 | 旧任务完成不覆盖新编辑 |
| 离线运行 | 模型及依赖准备完成后，断网可执行本地测试批次 |
| 性能记录 | 分别记录模型加载用时、总生成用时、峰值内存和成片音频长度 |

使用“生成总用时 ÷ 音频总时长”记录处理速度，并分别报告冷启动与模型已加载的结果。性能阈值在首次实测后制定，不将仓库其他机器的性能数据作为本机承诺。

## 12. 许可证与实现边界

Qwen3-TTS 官方仓库及本次查询的 1.7B 8bit MLX 模型卡标注 Apache-2.0，MLX-Audio 仓库标注 MIT。集成时锁定实际代码与模型版本，并保留相应许可证和声明。

本机系统声音的产品使用与分发规则需要在启用正式输出前另行核对；枚举出声音不等于已经确认输出的所有使用条件。

首版提供预设音色，不引入声音克隆、自由音色设计和模型训练。后续如扩展专属人物声音，应另行设计音色创建、参考音频保存和跨段一致性验证流程。

本次已完成文档能力核验和方案设计，尚未安装 MLX-Audio、下载权重、生成试听样例或测定本机性能。
