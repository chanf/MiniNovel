# MiniNovel 本地部署

当前部署的是 M1 版本：Web 服务、数据库、项目 API 和模型配置保存。生成模型、Skill、TTS 与视频合成将按后续里程碑接入。

入口：[scripts/deploy.sh](../scripts/deploy.sh)。脚本可从任意工作目录调用，自动定位项目根目录。

## 两种方式

| 项目 | 本机直接部署 | Docker 部署 |
| --- | --- | --- |
| 前置环境 | uv，脚本使用 Python 3.12 | Docker 引擎运行中、Docker Compose |
| 默认访问地址 | http://127.0.0.1:9513 | http://127.0.0.1:9513 |
| 数据 | 项目 `.data/`，可自定义绝对路径 | Compose 命名卷 `mininovel-data` |
| API Key | 本机 SQLite | 容器数据卷中的 SQLite |
| 应用进程 | 前台或脚本管理的后台进程 | 非 root 容器进程 |
| 后续 MLX TTS | 在 Apple Silicon Mac 上运行 | MLX 不在 Linux 容器中运行，需后续宿主服务连接 |

两种方式默认占用相同端口，不能同时启动；并行使用时指定不同端口。数据默认分开，不会共享 SQLite 数据库。

## 本机直接部署

先安装 uv。首次使用时，uv 可能下载 Python 3.12 和锁定的应用依赖，需要网络。

安装运行依赖：

```bash
./scripts/deploy.sh local install
```

前台运行，终端关闭或按 Ctrl-C 即停止。首次运行会安装依赖：

```bash
./scripts/deploy.sh local run
```

后台运行：

```bash
./scripts/deploy.sh local start
```

查看脚本管理的进程和健康状态：

```bash
./scripts/deploy.sh local status
```

查看最近 100 行日志：

```bash
./scripts/deploy.sh local logs
```

停止后台服务，保留项目数据：

```bash
./scripts/deploy.sh local stop
```

重新安装锁定依赖并重启：

```bash
./scripts/deploy.sh local restart
```

改用其他端口：

```bash
MININOVEL_PORT=5180 ./scripts/deploy.sh local start
```

自定义数据目录，例如目录名称含空格时保持引号：

```bash
MININOVEL_DATA_DIR="$HOME/Library/Application Support/MiniNovel" ./scripts/deploy.sh local start
```

后台 PID、进程标记和日志位于 `.deploy/local/`。脚本只停止有匹配部署标记的自有进程，不根据端口杀进程。`local status` 和 `local stop` 不会接管桌面预览或手动启动的服务；前台服务请在启动终端中停止。

若服务已运行，`start` 提示现有地址；变更端口或数据目录需使用 `restart`。同一代码目录只管理一个后台部署。

## Docker 部署

先启动 Docker Desktop 或你使用的 Docker 引擎。脚本不会自行开启系统应用或更改 Docker 设置。

构建并启动：

```bash
./scripts/deploy.sh docker start
```

首次构建需要网络拉取 Python 和 uv 基础镜像、应用依赖。Compose 等待容器健康检查通过后返回。

只构建镜像：

```bash
./scripts/deploy.sh docker build
```

查看状态：

```bash
./scripts/deploy.sh docker status
```

查看实时日志，按 Ctrl-C 只结束日志查看：

```bash
./scripts/deploy.sh docker logs
```

重新构建并创建容器，保留数据卷：

```bash
./scripts/deploy.sh docker restart
```

停止并移除应用容器，数据卷保留：

```bash
./scripts/deploy.sh docker stop
```

改用其他宿主端口：

```bash
MININOVEL_PORT=5180 ./scripts/deploy.sh docker start
```

Docker 默认项目名 `mininovel`；可通过 `MININOVEL_COMPOSE_PROJECT` 区分多个部署。同一部署的 start、stop、status 等命令必须使用相同项目名。数据卷名称随 Compose 项目名确定，通常为 `mininovel_mininovel-data`。改变项目名会使用另一个卷，原数据仍在旧卷中。

容器只将宿主 `127.0.0.1` 端口映射到容器服务，不默认开放给局域网。镜像构建上下文只包含运行文件和锁定依赖，排除 `.data/`、日志、环境文件和本机虚拟环境。

### Docker 与 API Key

本机与 Docker 都将供应商 API Key 存入 SQLite 的 `provider_secrets` 表，应用不再使用 Mac Keychain。容器凭据随命名卷保存，重建容器后仍保留。

普通配置与密钥在同一数据库事务中保存；界面和 API 只显示是否已配置，不返回明文。编辑时留空保留原密钥，填写新值则替换。

数据库未加密，备份包含密钥。数据目录、Docker 数据卷及其备份都需要限制访问；不要把数据库提交到仓库或随素材导出。密钥持久化已通过 Linux 可用的 SQLite 代码路径测试，但实际 Docker 启动仍需运行引擎后验证。

## 数据、备份和更新

- 本机数据目录包含 SQLite 数据库、API Key 及项目素材；备份也包含密钥。
- Docker 命名卷同时保存数据库与素材；停止、重建应用容器不会删除卷。
- 不要让本机服务与容器同时访问同一数据库文件。
- 备份前停止应用，复制本机完整数据目录，或用 Docker 卷备份工具备份完整命名卷。
- 恢复前停止服务；完整数据库备份包含 API Key，恢复或迁移数据目录后可继续使用。
- 更新代码后执行对应 `restart`；脚本不会拉取代码，不会自动删除数据或降级数据库。
- 本机安装仅保留运行依赖；开发测试时使用 `uv sync` 或 `uv run pytest -q` 恢复开发依赖。

## 排查

| 提示 | 处理 |
| --- | --- |
| uv 不存在 | 安装 uv 后重试 |
| Docker engine is not running | 启动 Docker 引擎后重试 |
| 端口已占用 | 停止你确认的原服务，或设置 `MININOVEL_PORT` |
| 健康检查失败 | 查看对应部署日志，检查数据目录权限和数据库版本 |
| 配置无法保存 | 查看日志，检查数据库目录的写入权限及磁盘空间 |
| 本地进程没有退出 | PID 记录保留；查看日志和进程状态后处理，脚本不强行杀其他进程 |

脚本帮助：

```bash
./scripts/deploy.sh --help
```
